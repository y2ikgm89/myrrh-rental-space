実装アプローチの比較

ウォームダーク × ブロンズ / Cormorant Garamond + Noto Sans JP / リッチモーション

A

トークン・ファースト（推奨）

戦略: @theme トークンを一括差し替え → Primitives 調整 → セクション個別磨き上げ

Phase 1 — public.css の @theme ブロック全面書き換え（カラー・タイポ・スペーシング）+ project-design-config.md 更新
Phase 2 — Header/Footer ダークテーマ対応 + 10 Primitives のスタイル刷新
Phase 3 — 17セクション個別刷新（Hero→CTA→リスト系→詳細系の順）
Phase 4 — モーション強化（GSAP ScrollTrigger演出追加）
Phase 5 — ページ統合（news+posts→journal）+ 全体磨き上げ

✦ 推奨理由: トークン差し替えだけで全コンポーネントが一斉にダーク化。段階的に品質を上げていける。既存アーキテクチャと完全整合。互換レイヤー(@layer compat)は削除してクリーンに。
B

コンポーネント・リビルド

戦略: デザインシステムを先にゼロから再構築 → セクションを新コンポーネントで組み直す

Phase 1 — 新デザインシステム設計（トークン＋新 Primitives 定義）
Phase 2 — 新 Primitives 実装（既存を破棄して書き直し）
Phase 3 — セクションを新コンポーネントで再実装
Phase 4 — Header/Footer/レイアウト再実装
Phase 5 — モーション・ページ統合

✦ リスク: 工数が2-3倍。既存の SectionRenderer/SectionWrapper アーキテクチャは優秀なので壊す理由がない。Primitives も構造は良い（Server Component、型安全）。見た目だけ変えれば良いものをゼロから書き直すのは過剰。
C

ページ・ファースト

戦略: ホームページを先に完成形まで作り込み → そのデザインを他ページに展開

Phase 1 — ホームページのみ完全刷新（トークン＋Hero＋全セクション＋モーション）
Phase 2 — ホームで確立したデザインをトークン化・抽象化
Phase 3 — 他ページに順次展開
Phase 4 — ページ統合・調整

✦ 注意: 1ページの完成度は高くなるが、他ページ展開時にトークンの後付け抽象化が必要。A と比べてトークン設計の手戻りリスクがある。ただし「完成形を先に見たい」場合には有効。

比較サマリー

観点 A. トークン・ファースト B. リビルド C. ページ・ファースト
工数 中 大 中〜大
