## 実装方針

**後方互換性を考慮しないクリーンな実装**: このプロジェクトは、最新の公式ベストプラクティスに準拠したクリーンでモダンな実装を優先します。古いバージョンや非推奨APIとの後方互換性は維持しません。すべての実装は、フレームワークとライブラリの最新の安定版を使用し、レガシーな回避策なしに公式推奨事項に従う必要があります。

## 公開ページ（デザイン重視）

### 1. ホームページ (`/`)
- **要件**:
  - Three.js/Pixi.jsとGSAP/Motionを使用した視覚的にインパクトのあるデザイン
  - レンタルスペースの魅力を伝える
  - 主要機能へのナビゲーション（予約、詳細ページ、お問い合わせ）
- **技術**:
  - Three.js/Pixi.jsによる3D/2Dビジュアル
    - **Three.js**: `@react-three/fiber`（React Three Fiber）を使用してReactコンポーネントとして宣言的に実装
      - `@react-three/drei`（ヘルパーライブラリ）を使用してよく使う3Dコンポーネントを効率的に実装
    - **Pixi.js**: `@pixi/react`を使用してReactコンポーネントとして実装
    - 動的インポート（`dynamic`）を使用してクライアントサイドのみでロード（SSR対策）
  - GSAP/Motionによるスムーズなアニメーション
    - **GSAP**: React専用ラッパーは不要、Client Componentsで直接使用
      - モジュラーインポート（必要なプラグインのみインポート）でバンドルサイズを最適化
      - `useEffect`や`useLayoutEffect`でアニメーションを初期化
      - 動的インポート（`dynamic`）を使用してクライアントサイドのみでロード（SSR対策）
      - 集中化されたGSAP設定ファイルでプラグイン登録を管理
    - **Motion**（旧Framer Motion）: React専用アニメーションライブラリ
      - `motion`パッケージを使用（`framer-motion`から移行）
      - Server Componentsとの統合を考慮した実装
  - レスポンシブデザイン

### ヘッダー & フッター（すべての公開ページ共通）
- **データベース統合**:
  - **データ取得**: Server Component（ルートレイアウト）でPrisma経由でデータベースから最新のナビゲーション情報を取得
  - **動的レンダリング**: データベースの内容に基づいてメニューとSNSアイコンを動的に表示
    - ヘッダー: `NavigationItems`テーブルから`type='header'`の項目を取得し、`order`順に表示
    - フッター: `NavigationItems`テーブルから`type='footer'`の項目と`SocialLinks`テーブルからSNSアイコンを取得
    - ロゴ: `Settings`テーブルから`headerLogoUrl`を取得
    - コピーライト: `Settings`テーブルから`footerCopyright`を取得
  - **ISR更新**: 管理画面で変更された場合、`revalidatePath('/')`でルートレイアウトを即座に再生成
  - **アクティブフラグ**: `isActive`が`true`の項目のみ表示
- **技術**:
  - Server Componentsによるデータ取得
  - ISR（Incremental Static Regeneration）によるキャッシュ戦略
  - `parentId`によるサブメニューの親子関係管理（最大1階層）

- **要件**:
  - **オーナーは開発者の介入なしでスペースを追加/編集可能**

  - **フォーム項目**:
    - **基本情報**: 名前、説明、住所、アクセス情報
    - **スペース情報**: 収容人数、面積、料金（時間単位、日単位）
    - **設備**: Wi-Fi、プロジェクター、ホワイトボードなど（チェックボックス形式）
    - **画像**: 複数画像アップロード（メイン画像1枚、サブ画像複数枚）
    - **公開設定**: 公開/非公開の切り替え
    - **営業時間**: 曜日別営業時間（開始時間、終了時間）
  - **リアルタイム更新**: 保存後、公開ページ（`/spaces/[id]`）に即座に反映
  - **バリデーション**:
    - 必須項目チェック（名前、説明、住所、料金など）
    - 画像サイズと形式チェック（最大10MB、JPEG/PNG/WebP形式）
    - 料金の妥当性チェック（非負数）
    - 営業時間の妥当性チェック（開始時間 < 終了時間）
- **技術**:
  - 画像アップロード（Supabase Storage）
  - リッチテキストエディタ（必要に応じて）
  - Zodスキーマによるフォームバリデーション（クライアントとサーバー両方）
  - Server Actions経由でPrismaにデータ保存

  - **ヘッダー編集**:
    - メニュー項目の追加、編集、削除、並び替え

    - メニュー項目の追加、編集、削除、並び替え
    - SNSアイコンの追加、編集、削除

    - コピーライト表示テキストの編集
  - **リアルタイム更新**: 保存後、公開ページのヘッダー/フッターに即座に反映
  - **バリデーション**:
    - メニュー項目名の必須チェック（1-100文字）
    - URL形式の妥当性チェック
    - メニュー項目数の上限（ヘッダー: 10項目、フッター: 15項目）

  - メニュー並び替えのドラッグ&ドロップ（react-beautiful-dndなど）

  - Next.js ISR（`revalidatePath('/')`）による公開ページの自動更新
- **デザインとコンテンツの分離**:
  - **開発者が管理**: CSS、レイアウト構造、コンポーネントの見た目
  - **オーナーが管理**: メニュー項目、リンク先、SNSアイコン、テキストコンテンツ
  - データベースから取得したコンテンツを開発者が定義したデザインテンプレートに適用

  - **SEO設定タブ**:
    - デフォルトメタディスクリプション、メタキーワード
    - デフォルトOGPタイトル、OGP説明
    - Google Analytics ID、Google Search Console ID
  - **予約設定タブ**:
    - デフォルト時間枠（15分、30分、60分）

    - キャンセルポリシー
    - 予約確認メール送信フラグ、管理者通知メール送信フラグ
  - **通知設定タブ**:
    - 各種通知の有効/無効（新規予約、予約変更、予約キャンセル、新規お問い合わせ）
    - 通知先メールアドレス（複数可能、カンマ区切り）
  - **その他タブ**:
    - タイムゾーン、言語設定
    - メンテナンスモード、メンテナンスメッセージ
  - **リアルタイム更新**: 保存後、公開ページに即座に反映
  - **バリデーション**:
    - メールアドレスの形式チェック（複数メールアドレスの検証）
    - URLの形式チェック（Supabase Storage URLのみ許可）
    - 電話番号の形式チェック
    - 営業時間の妥当性チェック（開始時間 < 終了時間）
    - 時間枠の妥当性チェック（最小時間 <= 最大時間）
- **技術**:
  - タブナビゲーションによる設定カテゴリの切り替え
  - 画像アップロード（Supabase Storage）
  - 画像プレビュー機能
  - Zodスキーマによるフォームバリデーション（クライアントとサーバー両方）
  - Server Actions経由でPrismaにデータ保存
  - Next.js ISR（`revalidatePath('/')`、`revalidateTag('site-settings', 'max')`）による公開ページの自動更新（stale-while-revalidate semantics）
- **詳細**: [`SETTINGS_REQUIREMENTS.md`](./SETTINGS_REQUIREMENTS.md) を参照してください

    - テーブル形式で顧客一覧を表示

    - 顧客検索（姓、名、メールアドレス、電話番号）
    - フィルタ（ステータス、アクティブ/非アクティブ）
    - ソート（姓、名、メールアドレス、最終予約日時、総予約回数、総利用金額）
    - ページネーション
    - URLクエリパラメータ管理: [`NUQS_REQUIREMENTS.md`](./NUQS_REQUIREMENTS.md)を参照
  - **顧客詳細表示**:
    - 顧客プロフィール表示・編集（基本情報、住所、ステータス、備考・メモ）
    - 顧客ステータス管理（新規、リピーター、VIP、非アクティブ、ブラックリスト）
    - 予約履歴一覧（関連する予約を日時順で表示、最新10件）
    - 統計情報表示（総予約回数、総利用金額、初回/最終予約日時）
  - **自動顧客作成**: 予約作成時にメールアドレスで顧客を検索、存在しなければ自動作成
  - **統計情報の自動更新**: 予約作成・更新・削除時に顧客の統計情報を自動更新
  - **リアルタイム更新**: 保存後、顧客一覧・詳細ページに即座に反映
  - **バリデーション**:
    - メールアドレスの形式チェック、重複チェック
    - 電話番号の形式チェック
    - 顧客ステータスの妥当性チェック
- **技術**:
  - **Server Components**: 顧客一覧ページはServer Componentで直接Prismaクエリを実行（`unstable_noStore()`を使用）
  - **Prisma最適化**: `select`で必要なフィールドのみ取得、`include`でN+1問題を回避、`Promise.all`で並列取得、`upsert`で顧客作成・更新を効率化、トランザクションで複数操作を保証
  - **キャッシング戦略**: 管理画面のデータは`unstable_noStore()`を使用（認証が必要なデータ）
  - **Server Actions**: データ変更操作（作成、更新、削除）のみに使用、認証チェック、エラーハンドリング、キャッシュ無効化を実装
  - Zodスキーマによるフォームバリデーション（クライアントとサーバー両方）
  - Next.js ISR（`revalidatePath('/admin/customers')`、`revalidateTag('customers', 'max')`）によるキャッシュ無効化（stale-while-revalidate semantics）
- **データベース**: Customersテーブル（詳細は[`DATABASE_DESIGN.md`](./DATABASE_DESIGN.md)を参照）
