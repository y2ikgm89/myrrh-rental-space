# テスト品質保護ルール

> テストの改ざんを防止し、品質を維持するためのルール

## 禁止事項

### 1. テストの skip 化

以下は**禁止**：
- `it.skip()`, `test.skip()`, `describe.skip()` の追加
- `xit()`, `xdescribe()` の使用
- `@pytest.mark.skip` の追加
- テストファイル全体のコメントアウト

### 2. アサーションの削除・緩和

以下は**禁止**：
- `expect()` や `assert` の削除
- `.toBe()` を `.toBeTruthy()` に緩和
- 具体的な期待値を曖昧な条件に変更
- エラーケースのテスト削除

### 3. Lint/CI 設定の緩和

以下は**禁止**：
- ESLint ルールの無効化（`// eslint-disable`）
- TypeScript strict モードの緩和
- CI パイプラインのテストステップ削除
- カバレッジ閾値の引き下げ

## 許可される変更

- テストの追加
- テストの改善（より厳密なアサーション）
- バグ修正に伴うテストの更新（実装と整合性を取る）
- リファクタリングに伴うテストの移動

## 違反時の対応

テストが失敗した場合：
1. **実装を修正する**（テストを変更しない）
2. 失敗の原因を特定し、コードを修正
3. 修正後、テストが通ることを確認

テスト自体にバグがある場合：
1. ユーザーに報告し、許可を得てから修正
2. 修正理由をコミットメッセージに明記
