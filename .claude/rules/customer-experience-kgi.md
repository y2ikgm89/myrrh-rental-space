# 顧客体験 KGI（品質の物差し）

品質の物差しは「テストが緑」ではない。**顧客が実際に遭わない 7 つの約束**で判定する。

|      | 約束               | 破れたときに顧客が見るもの                            |
| ---- | ------------------ | ----------------------------------------------------- |
| CX-1 | 空き枠の真実       | 「残り 3 枠」で申し込み、決済まで済ませて当日入れない |
| CX-2 | 金額の一意         | 提示額・請求額・領収書の数字が食い違う                |
| CX-3 | 入力の忠実         | 保存したはずの文言・写真が黙って消える                |
| CX-4 | 証跡の不可逆       | 「誰が何をしたか」を後から書き換えられる              |
| CX-5 | 時間の一貫         | 日付が 1 日ずれる／期間が永久に効かない               |
| CX-6 | 中断しない可用性   | デプロイで壊れる・落ちたことに気づけない              |
| CX-7 | 自分のデータの制御 | 退会したのに個人情報が残る                            |

ゲート・テスト・ドキュメントが緑でも、上記のいずれかが破れるなら未完了。

## 報酬ハッキングの温床（作らない・見つけたら消す）

次の 6 種は「守っているように見えるが何も守っていない」状態を作る。
**散文の理由付けは説明であって証明ではない。**

1. **vacuous-gate** — 正規表現が構造的に対象を見られない／1 件も拾えない
2. **unproven-exemption** — allowlist に載せるだけで理由が実測されていない
3. **drifted-prose** — コメント／docstring が実装とずれている
4. **transcribed-ssot** — 値一覧を 2 箇所に書いて片方だけ動く
5. **silent-skip** — 環境不足で黙って skip し緑に見える
6. **dead-mechanism** — 到達不能なコード・存在しない仕組みへの参照

除外コメントは「なぜその契約を満たせないか」しか言わない。
契約を消費する側がその不成立を想定しているかは、除外を見ても分からない。
除外を見つけたら依存コードを実際に開き、除外対象の値を流して確認する。
